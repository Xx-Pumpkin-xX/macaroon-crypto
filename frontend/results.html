Pentest findings

  1. F01OpenP1

    Two server processes revoking at the same time can lose one revocation.

    The demo runs a single process, which avoids it.

  2. F02FixedP2

    A token with invalid UTF-8 in its identifier crashed the service instead of returning 401.

    Commit a734aad, with regression tests.

  3. F03FixedP2

    If a file's revocation record went missing, revoked links worked again.

    Commit 49cf05f: the server now refuses access instead.

What this does not protect against

A malicious server
It holds the root keys, so it could mint any token, and it serves this page's JavaScript, so it could ship code that reads k from the link.
Content already downloaded
Revoking a link stops future downloads. A recipient who already has the file and k keeps them.
A leaked link
A link works for whoever holds it. A leaked share can be revoked; a leaked owner link cannot, because it has no share_id. The only fix then is deleting the file.
Metadata
The server still sees file size, timing and IP addresses. "Anonymous" means no account, not network anonymity.
Rollback
The server could serve an older version of the file. AES-GCM detects changed data, not an old but genuine copy.
